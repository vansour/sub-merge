# 导航预载缓存设计

日期：2026-08-07

## 背景

当前菜单栏切换是「先切页面、再载内容」：点击 tab 立即挂载页面，各页 `use_future` 挂载时拉数据，期间渲染空态/loading。需求改为「先载入内容、再显示页面」。

## 需求（用户确认的决策）

1. 点击菜单切换时**旧页面保持可见**，新页面内容就绪后瞬间切换
2. 应用于**全部 5 个页面**（概览/订阅源/组合订阅/预览/配置）
3. 加载期间**菜单项显示小转圈**指示
4. **缓存已加载数据**：切走的页面再次点回秒开，不重新等待
5. 首次加载**失败也切页**，页面展示页内错误 + 刷新按钮

## 架构

### 数据单元缓存（方案 B：集中数据缓存）

缓存按「数据单元」而非按页面划分。四个页面实际只有 4 种独立数据，多页共享：

| 单元 | 类型 | 消费页面 |
|------|------|---------|
| sources | `Vec<SourceDto>` | 概览、订阅源、组合订阅 |
| combineds | `Vec<CombinedDto>` | 组合订阅、预览（下拉选项） |
| preview | `PreviewSummary`（全部源） | 概览、预览 |
| config | `ConfigDto` | 配置 |

```rust
// 每个单元一份
enum CacheStatus { Idle, Loading, Ready, Error }
struct CacheState<T> {
    status: CacheStatus,
    data: Option<T>,
    error: String,
}
```

单元级缓存收益：切换秒开之外，顺带消除多页重复拉取（现状概览/订阅源/组合订阅各拉一次 sources），并让订阅源页 CRUD 后概览页数据同步（现状各页各自拉、不一致）。

### MainShell 承担加载编排（单点）

- 持有四份缓存信号 + `pending: Option<usize>`（加载中的目标 tab）
- 持有单飞守卫：同一单元已有 in-flight 时不发重复请求，完成后统一写缓存
- fetch 函数收拢到新模块 `crates/server/web/src/data.rs`（现散在各组件文件，`fetch_preview` 在 overview.rs 还是私有，需集中后由 MainShell 调用）
- 缓存 context provider，页面经 context 读写缓存

### 切换流程（点击菜单项）

1. 目标页所需单元全部 `Ready` → 立即 `tab.set` 秒开
2. 否则：旧页保持 → 并行拉取缺失单元 → 菜单项转圈 → 全部完成（成功或失败）后切换
3. 失败也切页，页面从缓存读 `error` 渲染页内错误

首次登录后的默认页（tab=0 概览）同样走预载流程：MainShell 挂载即触发所需单元加载，菜单项转圈，就绪后显示。

### 页面改造明细

| 页面 | 删掉 | 改为 |
|------|------|------|
| 概览 | 挂载 use_future | 从缓存读 sources+preview；刷新按钮 → 重拉两个单元 |
| 订阅源 | 挂载 use_future | 从缓存读 sources；增/删/启停/单行刷新成功后 → 重拉 sources 单元 |
| 组合订阅 | 挂载 use_future | 从缓存读 combineds+sources；保存/删除后 → 重拉 combineds 单元 |
| 预览 | 挂载 use_future | 下拉选项从缓存读 combineds；全部源的预览来自缓存单元；按组合过滤的预览为页面本地状态（过滤结果不进缓存）；刷新按当前选择：全部源→重拉单元，有过滤→本地重拉 |
| 配置 | 挂载 use_future | 从缓存读 config；轮换成功后 → 用响应回写 config 单元 + 更新 token 信号（现有逻辑保留） |

### 菜单项

`NavItem` 增加 `loading: bool` prop——pending/加载中的 tab 在菜单项内显示小转圈（复用现有 `Spinner` 组件）。

### 维持不变

- 各页刷新/CRUD 期间旧数据保留与按钮转圈现状
- 预览页过滤交互
- 错误展示形态（页内 error 文本）
- 登录/退出流程、App 启动 token 校验

## 边界处理

1. **快速连点多个 tab**：只认最后一次点击（`pending` 被覆盖）；先前的加载完成事件到达时发现 `pending` 已不是自己 → 忽略
2. **点击正在加载中的 tab**：无操作
3. **同一单元并发触发**：单飞守卫，重复请求不发
4. **加载期间退出登录**：MainShell 随 App 卸载，缓存一并丢弃，无泄漏
5. **单元加载失败**：Error 入缓存 → 照常切页 → 页内错误 → 点刷新重试
6. **401（过期 token）**：维持现状（启动时校验清除 + 页内显示错误），不新增处理
7. **加载中发生 CRUD**：CRUD 成功后的重拉以最后写入为准（最终一致，可接受）
8. **预览过滤视图与缓存「全部源」视图互不干扰**（本地信号 vs 缓存单元）

## 验证方式（前端无测试 harness，按 CLAUDE.md 既定流程）

- `dx build --web --release --debug-symbols false` → 0 警告
- `make smoke` → 9/9
- headless chrome + CDP 浏览器级验证：
  a. 首次点击 tab → 旧页保持 + 菜单项转圈 → 就绪后切换
  b. 切回已访问页 → 秒开，无转圈无等待
  c. 慢源场景（10s fixture）→ 概览/预览首次加载期间旧页保持可见
  d. 拉取失败场景 → 切页 + 页内错误
  e. CRUD 后缓存同步（订阅源页加源 → 概览页数据已更新）
- cargo 门禁照跑（fmt/clippy/test）

## 不做的事（YAGNI）

- 不做跨会话持久化缓存（刷新浏览器即清空，回到现状的重新拉取）
- 不做加载进度条/超时提示（菜单项转圈已足够）
- 不重构 CRUD 为乐观更新（保持现状的「操作后重拉」）
- 不为过滤视图建缓存（预览过滤结果本地化）
